# 矽利康用量估算（門窗周長估算）

從 CAD 門窗圖抓門窗型號尺寸主檔，從各樓層平面圖統計每個型號的實際數量，計算周長並換算
矽利康施工支數。本 skill 分三步驟，各步驟都有獨立腳本，中間產物是 JSON，方便中途檢查、
重跑單一步驟或换個樓層清單重新產生 Excel。

## 計算範圍：外框與玻璃必須分列

不要再把門窗總寬高的外周長當成全部矽利康。每個型號至少拆成：

1. **框封膠長度**：`寬×寬邊數 + 高×高邊數`。窗預設 2、2；落地門／門預設 1、2。
   若框與牆介面內外兩側都施作，另以「框打設面數」乘算，預設值不可擅自假定，應依使用者或施工規範設定。
2. **玻璃封膠長度**：逐片計算 `2×(玻璃寬+玻璃高)`，再將所有玻璃片加總。
3. **玻璃打設面數**：預設 2（內、外），在 Excel 設為黃色可調欄。
4. **單樘總打設長度**：`框封膠長度×框打設面數 + 玻璃單面周長合計×玻璃打設面數`。
5. **型號總長度**：單樘總打設長度 × 該型號數量。

相鄰玻璃共用同一支立料或橫料時，兩片玻璃靠該料的邊是兩道獨立收邊，應分別計入；不要把
共用分割線去重。玻璃尺寸若只由立面圖矩形推算，屬估算尺寸，不等同玻璃下料尺寸，Excel 備註必須標示資料來源。

## 玻璃分割辨識與可信度

優先從門窗詳圖中辨識每個編號範圍內的封閉窗格矩形，逐格輸出玻璃寬、高與周長。可輔助使用
`FIX` 屬性定義，以及推開／橫拉符號判斷格數與窗型，但符號本身不能提供完整玻璃尺寸。

每個型號都要輸出辨識狀態：

- **幾何辨識**：有完整封閉窗格，能逐片量得寬高。
- **分割推估**：能判斷格數或分割方向，但缺少完整封閉矩形；玻璃尺寸須人工補入或確認。
- **無法辨識**：詳圖缺少可用分割幾何與標記，不得以總寬高平均分配後冒充精確結果。

真實 CAD 常有部分窗型未畫完整窗格框線。遇到這種情況，採「自動辨識＋Excel 人工校正」：
已辨識玻璃逐片列出；未辨識型號保留可編輯的玻璃片數、各片寬高與打設面數，並以紅底提示。

腳本位於 `skills/silicone-usage-estimate/scripts/`。

## 前置確認

1. AutoCAD 必須已開啟（透過 `mcp__autocad__acad_status` 確認）。三個腳本都用
   `win32com.client.GetActiveObject('AutoCAD.Application')` 直連現有的 AutoCAD 程序，
   不會另外啟動新的 AutoCAD。
2. 需要知道兩件事：
   - **門窗圖**路徑（通常叫 A6門窗圖、門窗圖之類，內含編號對照表/圖例，每個編號只出現一次）
   - **樓層平面圖**的資料夾與檔名規則（例如 `{floor}_建築平面圖.dwg`），以及要跑哪些樓層代碼
3. **圖塊命名可能因專案而異**。預設抓 `_LCNo001`、`_LDNO001`、`_LOPN001` 這三種圖塊（在
   已驗證過的專案中，`_LCNo001` 用 `NO` 屬性、`_LDNO001`/`_LOPN001` 用 `U` 屬性存放編號，
   `D` 屬性存放門的防火時效）。若新專案抓不到資料，先用 `mcp__autocad__count_entities` 或
   簡單的 win32com 一次性腳本看一下該圖有哪些圖塊、屬性 tag 叫什麼，再用 `--block-names`
   參數調整。**不要假設新圖的圖塊命名跟舊專案一樣**，抓不到就如實回報，不要硬套。

## Step 1：抓門窗型號主檔

用 `open_drawing` 開啟門窗圖（如 A6門窗圖），確認是 ActiveDocument 後執行：

```bash
python skills/silicone-usage-estimate/scripts/extract_master.py --out master_dims.json
```

- 邏輯：找 `_LCNo001`/`_LDNO001`/`_LOPN001` 圖塊的 NO/U 屬性當編號，再找該圖塊插入點附近
  （預設 400 單位內）最近的「數字x數字」文字當寬x高（cm）。
- 輸出會印出：抓到幾個編號、幾個尺寸文字、有沒有編號重複但尺寸衝突（例如同編號兩種尺寸，
  這種要在最終回報時提醒使用者去 CAD 確認）、有沒有編號配對不到附近尺寸文字。
- 若某圖用不同圖塊名稱，加 `--block-names "圖塊1,圖塊2"`。

## Step 2：批次統計各樓層數量

先確認樓層平面圖檔名規則與資料夾路徑，跟使用者要來的樓層清單（順序就是最終 Excel 分頁的順序，
沒特別要求就用 B某F→1F→...→頂樓的習慣順序），執行：

```bash
python skills/silicone-usage-estimate/scripts/batch_extract_floors.py \
    --dir "D:/專案路徑/CAD底圖(建築)" \
    --pattern "{floor}_建築平面圖.dwg" \
    --floors B5F,B4F,B3F,B2F,B1F,1F,2F,3F,4F,5F,6F,7F,8F,9F,10F,11F,12F,PRF,R1F,R2F \
    --out floor_counts.json
```

- 這個腳本會逐一開啟每張樓層圖（如果已經開著就直接用，不重開也不會關掉）、掃描門窗編號圖塊、
  記錄該編號在這張圖出現幾次、然後關閉（除非本來就已開著）。
- 檔案較多、圖較大時這步會花點時間，屬正常現象，不用中途打斷重跑。
- 某樓層若完全沒有門窗標籤（例如屋突平台、機房），數量會是 0，這是正常結果，不是錯誤 —
  但建議打開該樓層圖面稍微確認一下實體數量（很少），避免真的是開啟失敗被誤判成"沒有"。
- 某樓層開啟失敗會記錄 `{"error": "..."}`，最終 Excel 該樓層分頁會顯示失敗訊息，不會靜默跳過。

## Step 3：產生 Excel

```bash
python skills/silicone-usage-estimate/scripts/generate_excel.py \
    --master master_dims.json --counts floor_counts.json \
    --out "outputs/門窗數量周長估算表.xlsx" --tube-length 6
```

- `--tube-length` 是矽利康每支(管)預設可施工公尺數，Excel 產出後每張分頁最上方仍有黃色
  儲存格可以再手動調整（全樓層彙總跟各樓層分頁的參數是各自獨立的儲存格，不連動，因為不同
  樓層可能用不同縫寬/規格）。
- 輸出結構：
  - **全樓層彙總**（第一個分頁）：每個編號一列，寬/高/總數量/各樓層分布橫向展開/總周長/用量。
  - **各樓層分頁**：依 `--floors` 給的順序排列，欄位＝類別/編號/寬/高/數量/寬邊數/高邊數/
    單支周長/總周長/用量(支管)/備註，都有小計列。
- 周長公式：`寬(cm)×寬邊數 + 高(cm)×高邊數`。窗類（窗/落地窗/小窗）預設寬邊數=2、高邊數=2
  （四邊都要打）；門類（門/防火門）預設寬邊數=1、高邊數=2（底部落地不需要矽利康，所以寬只算
  一邊）。這兩個係數欄在 Excel 裡是黃色可編輯儲存格，使用者可以逐支調整（例如某些落地窗底部
  也是外露需要打滿4邊、或子母門只有子扇要收邊）。
- 用量公式：`ROUNDUP(總周長(cm)/100 ÷ 每支公尺數, 0)`，無條件進位到下一整支。

## 資料缺口要誠實標記，不要用預設值蓋過去

- 樓層平面圖裡出現、但門窗主檔查無資料的編號：寬高留空、備註寫「門窗主檔查無此編號尺寸資料，
  需人工至CAD確認寬高」，紅底標記。周長/用量欄位也留空（公式需要寬高才能算）。
- 主檔本身同一編號有兩種衝突尺寸：extract_master.py 執行時會印出警告，最終回報時要提醒使用者
  去源頭圖面確認，不要自己猜一個「比較合理」的尺寸。
- 這些都是曾經在舊專案實際發生過的狀況（WB4 編號重複兩種尺寸、WB5 在平面圖上
  出現但主檔完全沒有資料且圖上也沒標尺寸文字），代表這類缺口在真實案子裡常見，務必保留這個
  誠實回報的機制，不要為了讓 Excel 看起來完整而自己補值。

## 回報格式

跑完後跟使用者說明：
1. Excel 輸出路徑，並用 SendUserFile 送出檔案。
2. 門窗主檔抓到幾個型號、有沒有配對失敗或尺寸衝突。
3. 各樓層統計摘要（總共幾個標籤、幾種型號），特別點出數量為 0 或開啟失敗的樓層。
4. 有紅底/缺口的編號逐一列出，並說明為什麼需要人工確認。
5. 提醒「寬邊數/高邊數」跟「每支公尺數」都是可調整的黃色儲存格，讓使用者知道可以直接在
   Excel 裡依現場狀況修改，不用回來重新產生一次。

## 中間檔輸出位置

`scripts/` 內的 `.ps1` 與 `.lsp` 會把中間檔（`*_raw.txt`、`silicone_seeds.*`、結果 CSV 等）讀寫在同一個資料夾：

- `.ps1`：預設為 `<專案根目錄>/outputs`（由腳本位置往上三層推算），也可用參數覆寫。
- `.lsp`：預設為 `%USERPROFILE%\Desktop\CL_CAD\outputs`；若設定環境變數 `SILICONE_OUT_DIR`，則改用該資料夾。
  AutoCAD 需在設定環境變數後重新啟動才會讀到。

## 常見問題

| 問題 | 原因 | 處理 |
|---|---|---|
| extract_master.py 抓到 0 個編號 | 這張圖不是用預期的圖塊命名，或編號屬性 tag 不是 NO/U | 用 win32com 一次性腳本列出圖塊名稱與屬性 tag，用 `--block-names` 調整，必要時也要調整程式碼裡找的屬性 tag 名稱 |
| 某樓層 distinct codes 特別少或 0 | 可能該樓層圖是圖塊(Block)包起來的，屬性讀不到內部圖塊 | 提醒使用者到 AutoCAD 對該樓層圖塊 EXPLODE 分解後重跑，或先確認是否真的無門窗 |
| 尺寸文字配對錯誤（抓到隔壁窗的尺寸） | 圖面排版密集，`--max-dist` 太大配對到別的窗 | 縮小 extract_master.py 的 `--max-dist` 再重跑，並人工抽查幾筆 |
| Excel 用量欄空白 | 該編號寬高其中一項缺資料，公式無法算 | 對照備註欄，先去源頭把尺寸補齊 |
